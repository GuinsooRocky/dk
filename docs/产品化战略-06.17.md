## 0. 前置事实校正（红队 Completeness 命中，先纠偏再立论）

在动笔前必须纠正一处贯穿全包的事实错误，否则路线图第一步就站在沙地上：

- **Onboarding 轨的开场断言"磁盘上没有 venv / 没有 requirements 文件"是错的。** 真实情况：`hub/.venv`、`telegram/.venv`、`feishu-claude/.venv`、`wecom/.venv`、`menubar/.venv` **五个 venv 真实存在**，且 `hub/`、`telegram/`、`feishu-claude/`、`wecom/` **四个 `requirements.txt` 真实存在**。唯一缺失的是 `core/` 没有 requirements。
- **后果**：Phase 0 不是"从零写依赖清单"，而是"**合并 4 份已有 manifest + 补 core/**"。最关键——那个被称为"最高风险单步"的 `lark-oapi` vs `python-telegram-bot` protobuf 冲突，**现在就能拿 5 个真实 venv 实测**，不必当未知数。这把 v1 最大的技术不确定性从"赌"降级为"今晚能验"。

## 1. 一句话定位 + 北极星

**DK 是一个原生 macOS 应用：在你自己的 Mac 上把 Claude Code 跑起来一次，你授权的人就能从他们手机上已有的聊天软件（Telegram / 飞书 / 企业微信）直接问它——对方零安装、零账号、零 VPN。**

**定位终裁（在 Discovery 的 A/B/C/D 四选项中）：以 C（"主人跑 Claude，授权的人直接聊进来"）为头牌叙事，用 D（原生精致）作交付外壳，以 B（安全可信）作贯穿底线。** A（对标 Anthropic Remote Control）明确放弃做正面叙事。

**为什么是 C 而非更稳的 B：**
- C 是竞品地图上**唯一的空格**。Anthropic Remote Control 是单用户、仅 Claude App、Max 档付费墙，结构上永远不会支持飞书/企微/第三方让别人聊进来。OpenClaw 渠道广但松（有 allowlist 绕过 bug、Baileys ToS 风险、无飞书无企微）。Tailscale+Ollama+Open WebUI 是 VPN 后的 web UI，访客必须装 VPN 建账号。**"多用户 host-serves-others + 中国 IM + 访客零安装 + 安全默认 + 原生 Mac 面板"这个交集，没有任何一家占据。**
- B（隐私安全）是**差异化理由（reason-to-believe）**，不是**品类（reason-to-care）**。"你家人终于能用上你电脑里的 AI"才是用户在意的事；"读默认只读、allowlist fail-closed"是证明它可信的机制。
- C 直接复用已有资产：fail-closed allowlist（`core/security.py`）+ 全局 concurrency=1 单飞（`core/runner.py`）正是安全多用户主机所需的原语，**已经在仓库里**。飞书 WS + 企微 smart-bot 是全竞品都缺的渠道。我们不是在建护城河，是已经站在里面。

**北极星指标**：**每周有 ≥1 个"访客"（非主人）成功收到一次 Claude 回复的活跃主机数**。这一个指标同时验证了"装得起来"（主机过了安装floor）、"有人用"（多用户叙事成立）、"在线可靠"（Mac 没睡死）。

## 2. 产品原则（3 条，不可妥协）

1. **操作隐形（Invisible Operations）。** 用户永不直面 Terminal、venv、配置文件、僵尸窗口。生命周期由**唯一一个 launchd 托管的 supervisor** 拥有，"启动/停止/开机自启"是开关不是命令。任何需要敲 Terminal 才能完成的操作，就等于没做完。

2. **状态永远清晰（Always-Clear Status）。** 任意位置 2 秒内能回答三问：**开着吗？此刻在干活吗？谁用过 / 有没有坏？** 一套状态词汇、**一色一义**，在菜单栏字形、渠道圆点、主控药丸三处完全一致复用。fail-closed allowlist 必须显示为可见的 `NEEDS SETUP`，绝不静默拒绝。Mac 睡眠这一物理极限要主动平静地讲出来，绝不让用户撞见。

3. **安全默认（Safe-by-Default）。** 开箱只读工具、allowlist fail-closed、绑定 127.0.0.1。写/Bash 是显式、沙箱化、明确标注的升级项——绝不默认、绝不静默。**任何让访客获得"读你整台 Mac 用户能读的东西"的权限升级，其同意门槛必须 ≥ WeChat 封号风险的同意门槛**（红队 Onboarding 命中：当前风险排序倒置，封号可恢复反而比 RCE 不可恢复门槛更高，必须扳正）。

## 3. 目标用户与真实可达性（诚实版，吸收 Onboarding 红队）

**最小可行用户（主机侧）的真相**：不是"非技术人员"，而是——

> **已经在付 Anthropic 钱、有一台愿意常开的 Mac、不怕 `open.feishu.cn` 开发者后台、且能接受"别人的消息会在我电脑上执行代码"的半技术 tinkerer。**

也就是**Persona 1（技术主机）+ 向导**，不是 Persona 2 自助。红队的判定我**采纳**：四道 floor 没有任何向导能降低——(1) 付费 Claude 账号、(2) 一台 24/7 常醒的 Mac、(3) 各平台开发者后台（Telegram 可过，飞书/企微残酷）、(4) 对"远程在我 Mac 执行代码"的知情同意（目标非技术用户结构上无法真正给出）。

**所以定位口径要扳正——区分"用"和"装"：**
- **"anyone can use it" 对访客（Persona 3）为真，对主机为假。** 向导真正的、可辩护的胜利是**消灭装后摩擦**（log-grep / 配置文件 / 重启的死循环），把主机从"开发者"降到"半技术 tinkerer"。它**不能**降到"奶奶"。
- **采用"管家/礼物"形态作为一等公民**：一个 tinkerer 给 N 个非技术访客装一次。把"为别人设置"做成正式的 onboarding 模式（主机替访客配 allowlist 条目，递一个二维码/deep-link 给对方）。这比"Persona 2 自助"更诚实，也匹配"访客才是主机愿意折腾的理由"。

**营销文案铁律**：主语"you run Claude once on your Mac"里的 you，对非技术人群不存在。对外一律说"**一个懂技术的朋友装一次，然后全家从已有 App 聊进来**"。不卖"奶奶能自己装"。

## 4. 核心体验：从安装到上线

### 4.1 非技术 onboarding 向导流（编号，原生 SwiftUI sheet）

**Screen 0 —— 资格预检（红队新增，堵无限 spinner）。**
明确告知"这需要一个付费 Claude 订阅（约 $X/月，来自 Anthropic）+ 一台常醒的 Mac。你有账号吗？[有 / 帮我开通→]"。**绝不让用户卡在转圈**。

**Step 1 —— Claude 安装 & 登录检查（阻塞门，过绿才放行）。** Detect→Guide→Verify 三态三卡：
- 1a 未安装 → 一键跑 Anthropic 官方原生安装器（零依赖、无 Node），原生 sheet 流式进度。
- 1b 已装未登录 → 跑一次 `claude` 让它自己开浏览器 OAuth，**轮询 `claude -p "ok"` 探针**确认*已登录*（`--version` 只证二进制存在，不证登录——多数流程漏的就是这步）。
- 1c 钥匙串锁/token 过期 → 原生包装 `claude doctor`/重登。
- **红队补丁**：要靠 stat `~/.local/bin/claude` + `/opt/homebrew/bin/claude` + 解析登录 shell PATH（Finder 启动的 .app 是 minimal PATH，别只信 `which`）。**每个探针硬上 60s 超时 + "大概率是什么问题"兜底文案**；要能区分"没登录"vs"登录了但没可用套餐"（看探针 error），后者路由到"去买套餐"卡。把解析出的绝对路径写进 `CLAUDE_CMD`（`core/config.py` 字段已存在）。

**Step 2 —— 选渠道（终裁：默认 Telegram-only）。** 非技术路径**默认只给 Telegram**（唯一 ~60s 可过的）。飞书/企微藏在"我已有飞书/企业微信开发者账号"勾选后（opt-in），重新定性为**工作路径**而非与 Telegram 平级的三个开关。WeChat **不在此屏**（见 §6）。

**Step 3 —— 逐渠道连接 sheet**（替代 `cp .env.example .env` + 手改）：
- 3a 注册 bot：deep-link + 截图步骤（各平台 token 创建是不可消除的技术残渣，只能软化）。
- 3b 粘贴 token：表单字段，实时校验，写 `.env`，之后不再显示。
- 3c **实时 allowlist 捕获**（最大的非技术胜利）：渠道进"学习模式"，提示"现在从手机给你的 bot 发一条消息"，捕获下一条入站 sender ID，渲染成可点的"把【你】加进白名单"。**这一步彻底干掉** `使用说明.md:48-51` 那套"空 ALLOWED_USERS → 前台跑 → grep `拒绝非白名单 from=ou_xxx` → 回填 → 重启"。allowlist 保持 fail-closed，空就显示为响亮的 `NEEDS SETUP` 行，绝不静默拒绝。

**Step 4 —— 安全/权限。** 三档预设映射 `claude.tools`：**只读**（`Read,Glob,Grep,WebFetch`，默认）/ 读+写 / 全权+沙箱。**红队补丁（不可妥协）**：读+写**和**全权都**必须先配置并验证沙箱**才能选中（不只全权要——"读+写无沙箱"才是陷阱）；且只要沙箱未验证激活，就把 `runner.py` 里硬编码的 `--permission-mode acceptEdits` 翻成 `default`（要人确认），否则一旦放开写权限，注入消息可无人值守改文件。**加 person 的措辞改成"这个人将能让你的 Claude 读取这台 Mac 上的文件"，每次添加都显示，不是只显示一次**。

**Step 5 —— 运行模式。** "开机自启"开关默认 **ON**（红队命中：`daemon/chatccbot.sh` 现状 `RunAtLoad=false` + `install≠start`，非技术主机重启一次产品就静默死了），开启后显示"已验证：重启后会自启"。**笔记本检测**（IOKit 电池存在）：若是笔记本，直白警告"合盖即离线，要 24/7 请用常插电常醒的 Mac"。"运行时保持 Mac 唤醒"开关包装 scoped/time-boxed `caffeinate`。

**Done** → 主窗口打开：Channels / Insights / Settings。

### 4.2 僵尸 Terminal 窗口如何变隐形（根因级根除）

**根因（两条，都在 `.command` 文件，不在 launchd）**：`menubar/启动菜单栏.command` 和 `run.sh` 都 `exec <python>` **在 Terminal 内**——窗口既*必须开着*（关了 SIGHUP 杀进程组），又*退出后留尸*（"[进程已完成]"）。全路径无 `nohup`/`setsid`/`disown`/`&`。launchd 是唯一逃出 SIGHUP 链的路径（reparent 到 PID 1，无 controlling TTY）。

**根除方案**：
- **退役两个 `.command` 文件**（`menubar/启动菜单栏.command` + `run.sh` 作为 Terminal 入口）。
- 原生 `.app`（`LSUIElement=1` 写进 `Info.plist`，编译期正确，替代 `menubar/app.py:17` 那个运行时设置的脆弱 hack）**结构性消灭**僵尸问题——永不 spawn Terminal。
- 一个进程（Swift app）同时拥有菜单栏项和窗口 → rumps 菜单栏（`menubar/app.py`）**退役不移植**。

## 5. UI/UX 蓝图

### 5.1 设计语言 & 状态词汇（终裁：4 态，不是 5 态）

单窗口 ~720×560，浅色，顶部分段 tab `Channels | Insights | Settings` + 常驻 footer。单一紫色 accent `#7C5CFF` 仅用于 active chrome。

**状态词汇终裁（红队 Completeness 命中"CONNECTING 无生产者"）：v1 是 4 态，不是 5 态。**

| 状态 | 色 | 字形 | 含义 |
|---|---|---|---|
| CONNECTED | `#34C759` | ● | 进程存活 + 干净运行（alive + last rc 干净 + backoff==1） |
| ERROR | `#FF3B30` | ● | 崩溃/认证拒绝/退避中 |
| OFF | `#8E8E93` | ○ | `enabled=false`，故意未拉起 |
| NEEDS SETUP | `#5AC8FA`（**改用青蓝，非紫**） | ◌ | enabled 但缺 token/secret 或 allowed_users 空 |

**两处终裁理由**：
- **砍掉 CONNECTING**：它需要 per-channel heartbeat，而该 heartbeat v1 不存在也没设计。v1 用"alive+干净+backoff==1 = CONNECTED"的 fallback，意味着 CONNECTING 永不触发。**与其留一个永不亮的动画态制造"5 态"假象，不如诚实做 4 态**。`transport_up` heartbeat → 真 CONNECTING 归 v2。所有"5-state"措辞全局改"4-state"。
- **NEEDS SETUP 改色**（红队 P2 命中）：原设计 NEEDS_SETUP 用紫 `#7C5CFF`，与 active-toggle/active-tab chrome 同色，违反自己"一色一义"原则。改 `#5AC8FA` 青蓝，紫色专留给 active chrome。

### 5.5 需要的后端改动（终裁：v1 只有一个净新 endpoint）

**`GET /supervisor`（v1 承重，唯一净新后端 endpoint）。** 现状：`supervisor.py` 的 `state` dict（`{name:{c,p,backoff}}`）知道每个子进程存活/退避/rc，但**只 `print`**（→ `/tmp/chatccbot.out.log` 丢弃），无 HTTP/IPC，且**无 `last_error` 捕获**（子进程 stderr 经 `Popen` 继承、无 pipe）。

最小合约：
```
GET /supervisor → { "channels":[
  {"name":"telegram","enabled":true,"state":"connected","pid":4821,
   "last_rc":null,"restarts":0,"backoff":1,"last_error":null},
  {"name":"feishu","enabled":true,"state":"error","pid":null,
   "last_rc":1,"restarts":3,"backoff":8,"last_error":"auth rejected: invalid app_secret"}
]}
```
实现要点：supervisor 改 `Popen` 用 pipe + per-child stderr ring buffer 捕获 `last_error`；`state` 服务端按显示优先级派生；走同一 127.0.0.1。**没有它 Channels tab 只能 On/Off 降级。**

> SQLite stats 是**第二个后端 add，但归 v2**（§9 解决 Reliability vs UI 的直接冲突）。learning-mode 捕获 seam 是**第三个 seam**，v1 需要（向导头牌"实时 ID 捕获"靠它），按 §11 与 `/supervisor` 同等严格度落地。

## 6. 渠道策略与微信裁决

### 6.1 微信终裁（采纳红队 WeChat 的最强结论）

**v1 不出任何个人微信 transport——不打包、不 sibling-dir、不 unsigned-plugin。** WeChat 在 UI 里是一个**禁用的信息行**："no safe way to connect a personal account. Use WeCom or Telegram. [Why?]"。**不做 toggle、不做 method radio、不做 risk-ack-to-enable 的 `WeChatRiskSheet`。**

**为什么比"off-by-default 加 BETA 徽章的插件"更进一步——我推翻了多条设计轨的"中间路线"：**

1. **"同意勾选"不是风险控制，是 foreknowledge 时间戳。** 勾一个框不会把封号概率降一个百分点，只证明"你知道还发了"。对丢了海外生命线账号的非技术用户，"但你勾了框"不是辩护。
2. **缓解措施全部不可验证/不可执行。** "human-like pacing 限速"——`core/` 里**根本没有出站限速器**，`Slots(1)` 限的是入站 Claude 任务不是出站微信发送；这是个不存在、且要对着腾讯保密的移动启发式持续调参、**没有测试 oracle** 的功能。"建议小号"是建议非强制。"per-friend allowlist 限爆炸半径"——allowlist 限的是*谁能调用*，封号由*协议指纹*触发，二者无关。"只读 Claude 工具"保护的是*主机 Mac*不是*微信账号*。**没有 oracle 的安全功能就是营销，在封号功能上营销安全，正是设计自称胜过 OpenClaw 的那个失败。**
3. **persona 防火墙是漏的。** 整个采用模型是"技术 Persona 1 替非技术 Persona 2/3 装"。所以"只对坚持的技术用户暴露微信"塌了——技术朋友会在**奶奶的 Mac 上用奶奶的主号**开微信。同意要绑定*账号所有权*而非*安装者老练度*，而你无法验证谁拥有那个微信账号 → 无法满足 → 砍而非 gate。
4. **海外用户是微信最坏受众**——产品定位的目标海外账号最可能登录失败（付了 PadLocal token 才发现连不上），登录成功又最可能被封，且封号代价（微信支付/身份/唯一海外纽带）最重。海外框架是**反对发货的论据，不是做精细版的论据**。
5. **PadLocal/Wechaty 是单厂、付费、灰产、无 SLA、必然腐烂**的依赖；连价格都无法陈述（设计自己说"pricing unverified"）。对一个 solo author 是永久维护税 + ToS/分发法律暴露。**unsigned plugin 框架不逃这点**——unsigned 反而读作"willful circumvention"（他们知道坏所以藏在 notarized app 外），争议中更糟。
6. **企微不解决"聊我的朋友"**：smart-bot 仅企业内部，external-contact API 是 consent-gated CRM 面（对方须扫员工码成"客户"、欢迎语 20s 一次性、~20-30 msg/min 限速），不是 P2P 好友 DM。所以今天没有负责任的方式完全满足 point 6——诚实的产品动作是在 UI 里说出来，不是藏起来。

**"重新开放微信"将变可接受的条件（五条全同时成立才考虑，目前 0 条成立）**：① transport 有可陈述的商业条款（价格+SLA）；② 只读/无自动出站（relay-only），且在 post-2017 海外账号上实测不触发登录封；③ transport 与分发是第三方、用户自取、author 不写不托管；④ 同意绑定账号所有权且能扛"技术朋友在奶奶主号上装"的失败模式；⑤ 每条缓解都有测试 oracle。

### 6.2 安全渠道的计划

- **Telegram —— 保留，设为推荐默认。** 官方 Bot API、长轮询、零封号风险、最低摩擦。设为向导首屏"recommended, easiest"。它让 Category 3（"主人跑 Claude，朋友聊进来"）对非技术多数派为真。
- **飞书 —— 保留，是护城河。** WS 长连接（`feishu_ws_server.py`）= **无公网回调 / 无 ngrok**，OpenClaw 与西方 OSS 都没有。**退役 legacy webhook/Flask 变体**（`feishu_app_server.py` + `feishu_send.py` + `daemon/feishu-daemon.sh`，flag 待删不静默删）。
- **企微 —— 保留，但诚实标注。** 官方 smart-bot 长连接（`wecom_ws_server.py`），无回调无主体校验，可个人组建团队。**UI 精确标注"for your org / consenting customers — NOT personal-WeChat friends"**，杀死"企微=能聊个人微信"的头号误解。**绝不**营销企微解决 point 6。

### 6.3 渠道插件契约（保"加渠道=写薄壳"）

新渠道 = 薄壳：① 收平台入站；② 执行 fail-closed allowlist（`core/security.py` 不变）；③ `core/hub_client.ask_hub` → `POST 127.0.0.1:8787/chat`；④ 经 `core/chunking`+`core/dedup` 回复。**不碰 claude**（只有 Hub fork claude）。manifest 加 `trust_tier = "safe" | "experimental_risk"` 字段驱动 UI 分区——但 v1 没有任何 `experimental_risk` 渠道发货（微信被砍），该字段为 v2/第三方插件预留。

## 7. 打包与分发

**终裁栈：SwiftUI 原生外壳 + 单解释器 PyInstaller `--onedir` Python sidecar（Hub+全渠道），Xcode 签名/公证，Sparkle 2 自动更新。**

理由钉到目标：只有原生 AppKit/SwiftUI 能把参考 UI（真 tab / list-rows+toggle / Swift Charts）渲染成"企业级应用"而非"窗口里的网页"（Tauri/Electron 会读作 hacker tool，正是用户在划的线）；Swift 用 `Process`/launchd 拉 sidecar **永不 spawn Terminal**（根除僵尸）；SwiftUI 外壳 idle 几 MB（满足低内存）；notarized .app 无 Gatekeeper 警告（企业级）。

**进程所有权终裁（红队 Completeness 命中"三种互斥图"）：launchd 拥有 sidecar，Swift app 是只读 viewer + 控制器，绝不用 `Process` 自己 spawn sidecar。**
- 理由：若 Swift app 用 `Process` spawn，退出 app 就孤儿/杀死 bots，破坏 always-on。launchd 拥有 → "Start/Stop" = `launchctl bootstrap/bootout`，**app 退出绝不停 bots**。这是唯一与"always-on"自洽的架构。
```
launchd LaunchAgent (KeepAlive=Crashed, RunAtLoad 由"开机自启"开关控)
   └─ supervisor.py ──spawn──► hub + enabled channels (单解释器, 多进程, headless)
        └─ 暴露 /status /stats /supervisor on 127.0.0.1
   SwiftUI app = NSStatusItem + 懒加载窗口 = 只读 viewer + 写 config + launchctl 控 agent
```

**迁移路径**：
- **Phase 0（硬阻塞）**：合并 4 份真实 `requirements.txt` + 补 core/ → 一份根 `requirements.txt`（py3.12）；**现在就拿 5 个真实 venv 实测 `lark-oapi` vs `python-telegram-bot` protobuf 共存**。若不可调和 → 退守"多进程但 pin 共享 protobuf"。
- **Phase 1**：`supervisor.py:32 _venv_py()` 折叠到单解释器（保多进程，仅折叠解释器）。
- **Phase 2**：PyInstaller `--onedir`（**非 onefile**，onefile 破公证）；bundle certifi（设 `SSL_CERT_FILE` 为自带 cacert）；bundle 或检测 ffmpeg。
- **Phase 3**：`dist/hub/` 进 `Contents/Resources/`；NSStatusItem 替 rumps。
- **Phase 4**：签名/公证/staple/Sparkle appcast。

**签名/公证**：Developer ID Application 证书（$99/yr）、hardened runtime、**inside-out 签 sherpa-onnx/numpy/grpc 嵌套 dylib**（首次签名预算 1-2 天，标准 Python-on-Mac 税）、`notarytool submit --wait` + `stapler`。Briefcase 留作签名自动化后备。

**Claude-CLI 依赖处理（硬地板，永不打包）**：`core/runner.py:57` `subprocess.run([cfg.claude_cmd,...])`，默认裸 `"claude"`。app 是 claude 的 *gateway*。realistic v1 承诺 = "**非技术渠道设置，前提 Claude 已装已登录**"，不是"含 Claude 的 turnkey"。靠 §4 向导 Step 1 detect→install→login-probe 跨越，写绝对路径进 `CLAUDE_CMD`。

**自动更新分离**：Sparkle 2（EdDSA + 静态 appcast on GitHub Releases）只更新外壳+sidecar；**Claude Code 自更新**，Sparkle 不碰。

**更新作为体验（红队 Completeness 命中，补 Sparkle 机制外的人因）**：① 稳定/beta 双通道（v1 只稳定）；② **更新前检查 `/status.busy`，busy 则推迟更新**（concurrency=1 下错时更新会丢用户请求）；③ 坏 build 回滚走 appcast 撤版；④ 非技术用户更新后给一行原生通知"已更新到 vX"。

**SenseVoice 模型（终裁尺寸口径）**：模型 **~1GB**（红队两轨给了 228MB vs 1GB 两个数，**统一按 ~1GB 报**，宁可高估管理用户预期；228MB 疑似只算单个 onnx）。**不打包**，首次启用语音时**懒下载**到 app-owned 目录，设 `SENSEVOICE_DIR`。**语音是否进 v1：v1 不含语音**（见 §9，模型分发+CDN+隐私是没人端到端 own 的支持/隐私事件，砍出 v1 降风险）。

## 8. 可靠性·内存·安全

### 8.1 进程/内存（终裁：保进程拆分，折叠 venv）

| 轴 | 现状 | 终裁 | 理由 |
|---|---|---|---|
| 进程模型 | 多进程 Popen | **保留** | 崩溃隔离真实且便宜；薄管道/单脑边界是架构最佳属性；self-heal 靠子进程独立 |
| 解释器/venv | 5 个 venv，~617MB | **折叠到 1** | venv 只为 pip 隔离（隔离来自进程边界非 venv），是头号打包障碍 + 4× 冗余 base RSS |

**不合并成单 asyncio 进程**（v2 再议）：那会用崩溃隔离换 ~3 解释器 base RSS（几十 MB），且单渠道阻塞 bug 会卡住 Hub event loop。

**内存预算（可测，非口号）**：IDLE ≤250MB 总 RSS（折叠后：1 Hub ~40-60MB + 1-3 channel waiter ~30-50MB 共享解释器 + SwiftUI 外壳 ~30-80MB）；BUSY = idle + claude 任务本身，`Slots(1)` 全局单飞硬封顶（`runner.py:14-22`），busy 即时回不排队。**测量用 `footprint`/`vmmap` 不用 `ps`**（`ps rss` 巨幅高估共享页，用户 MK 项目史已证）；General tab 显示 `footprint` 算出的真实 dirty memory，让"低成本"可证。

### 8.2 Always-on & Mac 睡眠诚实

两层 self-heal **保留不变**：launchd `KeepAlive=Crashed` 重启 supervisor + supervisor 指数退避 `1→30s` 重启子进程。差距纯在可观测——经 `/supervisor` 暴露（§5.5）。

**Mac 睡眠 = 离线是物理极限，诚实缓解不假装解决**，三层：① 常驻 footer chip 情境升级（`☀️ Mac awake` → `🌙 Mac will sleep in ~2min → bots offline [Keep awake 1h]` → 唤醒后 `💤 Was offline 6h while Mac slept`）；② `caffeinate` 为 **opt-in time-boxed assertion，绝不静默永久唤醒**（笔记本电池/热陷阱）；③ **笔记本检测后直白警告 + 给访客诚实回复**"The assistant's computer is asleep right now"，而非静默（不让非技术访客以为坏了）。**不承诺合盖运行**。

### 8.3 安全可见化（保原语，做可读）

**verbatim 保留**（都对）：只读默认工具、fail-closed allowlist、127.0.0.1 绑定、untrusted-input prompt fencing、sandbox `--settings` 透传 + `failIfUnavailable:true`。

**productize**：
- 只读默认做成**安心徽章** `ⓘ Read-only · safe`，不是警告。
- 三档预设替代裸 tools 字符串；**读+写 与 全权 都强制沙箱验证后才可选 + 沙箱未验证则 `acceptEdits→default`**（§4 Step 4 红队补丁，承重）。
- fail-closed 做成可见 `NEEDS SETUP` 行 + 行内修复 CTA，绝不静默拒绝。
- 实时 ID 捕获干掉 log-grep allowlist 死循环。
- **per-guest concurrency 礼貌**（红队命中 DoS）：busy 时告诉访客"someone else is using it, try again in ~Ns"带真实剩余 timeout，不是裸"busy"。

### 8.4 隐私/数据处理（红队 Completeness 命中"声称为价值却从未成策略"——补一节）

**数据真相**：`/stats` 存 `last_text`（≤120 字入站），`hub.log` 存日志。多用户产品里**主机磁盘存了所有人（含家人/伴侣）的消息片段**，访客"零安装零账号"也**零同意**，却让消息文本落在别人盘上。

**v1 数据策略（必须有）**：① 明确存什么（仅 `last_text` 深度 1 + `hub.log`）、存哪（`work_dir/.logs`）；② **v1 不引入 SQLite `events.text_120` 持久化**（§9）——把"持久化每条消息 120 字预览到盘"推到 v2 并附保留策略，v1 不背这个隐私债；③ Settings 加"Clear history"（**走废纸篓不 rm**，遵用户全局 no-auto-delete 立场）；④ Connect/Add-person sheet 文案告知访客"消息片段会存在主机上"。
