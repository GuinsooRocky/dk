# DK 上下文/会话管理架构方案（拍板稿）

> 来源：ultracode 调研（4 策略族深挖 + claude 原语实测 + headroom 评估）。
> 以**原语实测为权威**。锚定代码：`runner.Sessions`(L29-45)、`hub.chat`(L75-110)、`build_prompt`(config.py L225)、`_run_cli`(L59-92)。

## 0. 一句话主张

DK 不该把"会话"管成一坨只增不减的 transcript，而该拆成**三层职责分明的东西**：
- **第①层 会话分线**：多 session_id + SQLite 注册表落盘（话题各走各的线）
- **第②层 单线不爆**：token 越线就发 `/compact` 让 claude 自己原地瘦身
- **第③层 事实不丢**：per-user 一份 `CLAUDE.md`，claude 自动加载

三层全压在 claude 现成原语上，**DK 只自建两样**：一张 SQLite 会话注册表 + 一个轮间空窗压缩触发器。常态零操作，想管理时一句中文就够。

核心判断：DK 是"装得下"的个人规模（实测 9 个会话 2 天才 31 行有意义对话）→ **不做向量检索、不做独立记忆库、不做自动话题分线**（都是为"装不下"的规模设计的，搬过来是过度工程）。

## 1. 三层数据流

```
一条 IM 消息 → hub.chat 入口(单飞闸)
  ├ text 以 "/" 开头或管理意图 → 第①层命令拦截(列/切/新建/改名/分叉/在哪)，不调 claude，直接回执
  └ 普通对话 → 第①层查 active 线拿 sid
              → 第③层注入该 user 的 CLAUDE.md(claude auto-discovery，--setting-sources project 堵泄漏)
              → run_claude(action, sid): new→--session-id / resume→--resume / fork→--resume --fork-session
              → 记 usage.input_tokens
              → 第②层: est_tokens>120K 且距上次压缩≥3轮 → 标记待压缩
                      → 轮间空窗: 备份 jsonl → 发 /compact → 验 boundary
```

三层边界：①只管"消息归哪条线"产出 sid；②只管"这条线别爆"，信号来自①的 est_tokens；③只管"跨线跨重启不丢的事实"，故意不塞进任何一条线（否则换线就忘）。

## 2. 数据模型

| 层 | 存什么 | 载体 | 重启后 |
|---|---|---|---|
| 会话组① | `(owner_key, thread_id, name, parent_id, is_active, turn_count, est_tokens, ts)` | SQLite `~/.chat-cc-bot/threads.db` | 读回 active 线 sid → --resume 续 |
| 上下文② | transcript + compact 摘要 | claude 自己的 jsonl + DK 压缩前备份 `~/.chat-cc-bot/archive/<sid>.<ts>.jsonl` | jsonl 在磁盘，sid 在库 → 接得回 |
| 记忆③ | 身份/称呼/硬偏好/长期事实 | per-user `CLAUDE.md` + 影子草稿 `MEMORY.draft.md` | 文件在磁盘，claude 每轮 fresh re-read |

```sql
CREATE TABLE threads (
  owner_key   TEXT NOT NULL,   -- "channel:chat_id"，沿用现状隔离语义
  thread_id   TEXT NOT NULL,   -- DK uuid4()，直接当 claude --session-id（实测可预分配）
  name        TEXT,            -- 用户起的中文名 / "未命名-N"
  parent_id   TEXT,            -- fork 来源（claude 不记血缘，DK 自存）
  is_active   INTEGER DEFAULT 0, -- 该 owner_key 下唯一承接日常消息的线
  turn_count  INTEGER DEFAULT 0,
  est_tokens  INTEGER DEFAULT 0, -- 上一轮 usage.input_tokens，喂第②层触发器
  created_at  REAL, last_used_at REAL,
  PRIMARY KEY (owner_key, thread_id)
);
```

key 决策：①`thread_id` 直接 = claude session_id（实测 `--session-id <我给的UUID>` 原样返回，DK 自己 uuid4() 当主键，消除"先跑一轮拿 sid"竞态）；②`owner_key` 仍 `channel:chat_id`，多话题靠它下面挂多条 thread_id。

**hub 重启**：`is_active` 和 sid 全落 SQLite，重启后第一条消息 `SELECT thread_id WHERE owner_key=? AND is_active=1` 读回 --resume 接上。**最低成本最高收益的第一刀，MVP 必做。**

## 3. 上下文维护回路

触发→备份→压缩→验证，跑在"轮间空窗"不占用户当前消息：
1. 答完判断 `est_tokens > 120K 且 距上次压缩≥3轮`
2. 备份：`cp <sid>.jsonl → archive/<sid>.<ts>.jsonl`（安全网，绝不因压缩丢线）
3. 压缩：`claude -p "/compact 保留:用户身份/偏好/未完成任务/关键决定; 丢弃:闲聊与已完成琐碎" --resume <sid>`
4. 验证：grep compact_boundary 拿 pre/postTokens；失败→不动留备份下轮再试

阈值 120K 理由：input_tokens 每次 json 白给零探测成本；硬线 167K(83.5%×200K)留 47K 垫；实测压缩率 87% → 120K 压成 ~16K。
**白嫖 `/compact` 不自建摘要**：实测可用、可带聚焦指令、对续接透明、87% 压缩、claude 内置 8 段式结构化摘要质量稳定。
单飞处理：压缩是完整 claude 调用(18-23s)，不抢主回路名额 → 第二低优 slot 或轮间 executor。

## 4. 用户接触面（纯聊天命令体系）

斜杠 + 自然语言双轨，hub 层拦截不进 claude：

| 操作 | 斜杠 | 自然语言 | 行为 |
|---|---|---|---|
| 列线 | `/threads` | "我都有哪些会话" | `1.工作(活跃,23轮) 2.出海(5轮)` 带轮数 |
| 切线 | `/switch 工作`/`/switch 1` | "切到 onlychat 那条" | 名字模糊+编号双认 |
| 新建 | `/new 出海SEO` | "换个话题聊X" | 建线+设active；不带名→"未命名-N" |
| 分叉 | `/fork 试另一方案` | "基于刚才分个岔" | 继承历史+新sid+记parent |
| 改名/在哪 | `/rename`/`/here` | — | — |
| 记事实 | `/记 以后叫我老王` | "以后叫我老王/别用emoji" | 异步写 CLAUDE.md |
| 查/忘记忆 | `/记忆` | "你记了我啥" | 念文件；删=改文件(确认后) |

铁律：①编号+名字双寻址；②每次切/建后回执带"你现在在哪条线+几轮"（IM 没 tab 高亮，这是唯一当前态指示器）。

## 5. 映射 claude 原语（实测）

| 机制 | claude 能力 | 实测 |
|---|---|---|
| 新建线首发 | `--session-id <UUID>` | ✅ 原样返回可预分配 |
| 续接 | `--resume <sid>` | ✅ 稳定、full history |
| 分叉 | `--resume <parent> --fork-session` | ✅ 新sid+继承父+copy-on-write隔离 |
| 越线压缩 | `claude -p "/compact" --resume` | ✅ **能用** 87%压缩透明 |
| 自动压缩 | — | ❌ claude 不给(-p永不自触发)→DK自建触发器 |
| 长期记忆注入 | `CLAUDE.md` auto-discovery | ✅ 自动加载，resume中改文件下轮生效 |
| **堵 owner 泄漏** | `--setting-sources project` | ✅ **必做**，否则 owner 私人全局 CLAUDE.md+RTK.md 注入进每个远程用户会话(实测泄漏) |
| 临时注入 | `--append-system-prompt` | ✅ 备选，写中性事实别写命令式 |

DK 必自建三样：会话注册表（headless 无 picker/列表）、自动压缩触发器、按 user×话题的隔离与血缘。存储一律 SQLite/markdown 落盘，不引 Redis/向量库。

## 6. 关键取舍拍板

| 分叉 | 选择 | 理由 |
|---|---|---|
| 自动 vs 手动分线 | 手动命名+隐式 active 兜底，**不自动分线** | 自动分线要么每轮多调 claude(破单飞)、要么超时分段(指代断)，失败比解决的更糟 |
| 自动 vs 手动维护 | 自动为主(token阈值)+手动逃生口 | 低摩擦、零探测成本 |
| 压缩 原生 vs 自建 | 白嫖 `/compact` | 实测能用透明87% |
| 记忆 隔离 vs 共享 | per-user 隔离+`--setting-sources project` | 原生全局会串台(实测泄漏) |
| 记忆写入 | 显式立即生效+影子草稿待批，bot不自动落地 | 单人误记代价高 |
| 检索 轻 vs 重 | 蒸馏注入/不做向量RAG | 31行/3KB装得下，注入比检索便宜3-4.5倍 |
| fork当话题树 | 能做但克制(仅显式低频，软上限2-3层) | 每fork物理复制整份父历史 |
| sid失效 | 不静默新开，回执问用户 | 现状pop静默丢史违反never-delete |

## 7. 实现草图

**新增**：`core/threads.py`(SQLite ThreadRegistry)、`core/memory.py`(CLAUDE.md读写)、`core/maintain.py`(should_compact+compact)、`core/commands.py`(斜杠/意图拦截)。
**改现有**：
- `core/runner.py`：`_run_cli` 加 `--setting-sources project`(修泄漏，一行) + 返回值加 usage + `run_claude` 的 resume 参拆成 action{new,resume,fork}+sid；删 Sessions 类。
- `hub/app.py`：`chat()` 在 build_prompt 前插 `commands.intercept`；SESSIONS.get/update 换 REGISTRY.get_active/bump；L104 后接 should_compact 触发后台压缩。
- `core/config.py`：Config 加 `compact_threshold=120_000`、`min_turns_between_compact=3`；build_prompt 不动。

实现坑：算 jsonl proj 目录名要按 resolved path + 全部 `_→-`、`/→-`，macOS `/tmp`→`/private/tmp`，别猜。

## 8. 分期

| 期 | 内容 | 工作量 | 解决 |
|---|---|---|---|
| **MVP** | ①sid落盘替换内存dict ②`--setting-sources project`修泄漏 ③sid失效不静默新开 | ~1-1.5天 | 重启全忘(最高频)+泄漏+静默丢史 |
| 增强 | ④`/compact`自动触发器 ⑤per-user CLAUDE.md记忆+`/记` ⑥命令体系/threads /switch /new /here | ~2-3天 | 有界+事实不丢+分线 |
| 高级 | ⑦`/fork`话题树 ⑧影子草稿待批 ⑨蒸馏注入(按需) ⑩30天未用折叠提示(不删) | ~2-3天按需 | 完善+误记防御 |

MVP 只做"会话不失忆+不泄漏+失败安全"三件，不碰压缩/多线/记忆——失败模式1(重启全忘)单 sid 落盘一刀解决 80% 痛点。

## 9. headroom 评估结论（并入）

不 adopt（它是 coding-agent 工具噪声压缩器，省的是工具输出/日志/RAG；DK 是对话历史为主，落它 TEXT 桶压不动；且 DK 用 --resume，对话历史不在 DK 构造的 prompt 里，proxy 压缩还会打断 prompt cache 反而慢；订阅制省 token 不省钱）。借鉴三个思想（已融入本架构）：CCR 可逆→压缩前备份 jsonl(§3)；learn 的 CLAUDE.md marker 块合并→记忆写入协议(§2/③)；内容分类反用→判闲聊vs任务(增强期)。

## 待拍板开放问题

1. 压缩跑哪：第二 low-priority slot(推荐) vs 轮间 executor
2. 阈值 120K 是否接受（可调 100K~140K）
3. 影子草稿要不要做（MVP 倾向不做，只显式 `/记`）
4. 关 claude 原生 auto-memory（让记忆完全由 DK 双轨掌控）
5. 群聊记忆按"群"还是"群里每个人"
6. `--setting-sources project` 会丢 owner 全局 CLAUDE.md：你自用 DK 时是否要保留你的全局偏好（要则复制进 DK 专用记忆文件）
